# 歌词滚动算法

本文说明 RLCD 4.2 面板如何在放不下时显示一整句歌词，以及每个参数为什么取这个值。实现见 `firmware/targets/waveshare_rlcd_42/main` 的 `screens.cpp`（`lyric_row`）、`panel_logic.cpp`（`lyric_scroll_offset`、`apply_now_playing`）和 `cjk_font.cpp`（`boundary_at_or_before`、`window_width`、`tail_start`）。

## 约束

- 歌词页一行 364 px、时钟页右栏一行 216 px，都是 12 px 字号（汉字 24 px 一列，ASCII 12 px 一列）。时钟页那一栏只有歌词页的 59 % 宽。
- 一句中文歌词常有 20–25 个字（60–75 字节），一行最多显示 15 个左右，其余必须滚动才能看到。
- 面板 4 fps 组帧，每帧整帧写入；帧内容不变时不发 SPI。换句那一刻额外组一帧，新句子不必等到下一个 250 ms 边界才出现在屏上。
- Bridge 每秒发布一次 `now_playing`。有毫秒时间轴时，换句由播放位置决定，不再等下一条发布；没有时间轴的来源最多比实际换句晚一个发布周期（1 s）。

## 数据来源

Bridge 每次发布 `now_playing` 都给出这一行及其后四行、当前行下标，以及可选的 `line_end`（这一行结束、下一行开始的位置，秒）。面板把 `line_end` 只当作**上限**用，见下。

歌词文件本身带毫秒时间戳，Bridge 按毫秒解析并原样下发：`position_ms` 是播放位置，`line_times` 是窗口里每一行在歌曲里的起点（与 `lines` 一一对应）。面板据此把歌曲放在自己的时间轴上：

```
position = position_ms + min(now − 收到发布的时刻, 3000 ms)   # 播放中才推进
current  = 最后一个 line_times[i] ≤ position 的行   # 没有下一条发布也照样换句
age      = position − line_times[current]          # 这一句已经唱了多久
budget   = line_times[current + 1] − line_times[current]   # 这一句有多长；没有后继则为 0
```

外推有上限：Bridge 每秒发布一次，超过 3 秒没有新发布就说明链路或 Bridge 停了，面板必须停在最后听到的位置，而不是用本地时钟把歌词一路带过整首歌 —— 否则等帧恢复时看起来就是"跳了很多秒"。

这样滚动按歌曲的节拍走：句子长短由时间戳给出，不用按秒取整；换句发生在时间戳的那一刻，而不是发布到达的那一刻。`position_ms` 与 `line_times` 缺省时，面板退回按发布时刻计时的旧路径：`age` 从"这一行出现"起算，`budget` 取 `line_end − position`。

## 算法

对正在唱的那一行（`row == 0`），已知整行宽度 `width` 与这一行可用宽度 `room`：

```
travel   = tail_start(line, room)          # 整条尾巴能放进这一行的最左字形边界
text_col = ceil(width / 12)                # 整行有多少列文字
content  = 900 ms + 100 ms × text_col      # 读这行需要多久

budget   = 这一行的长度                    # 有时间轴时取自时间戳；
                                          # 否则是首次收到这行时算的 (line_end − position) × 1000
lead     = 900 ms                          # 行首静置，最多这么多
motion   = content
if budget > 0:
    usable = max(0, budget − 400 ms)       # 收尾必须留出一帧
    lead   = min(lead, usable / 3)         # 时间紧时先压缩停顿，不压缩滚动
    motion = min(content, usable − lead)

step(t)  = min(ceil(travel/12), (t − lead) × ceil(travel/12) / motion)   # t < lead 时为 0
start    = boundary_at_or_before(line, min(step × 12, travel))
visible  = window_width(line, start, room)     # 从 start 起能完整放下的整字
绘制      = clip(x, top, visible, 行高) 内，把整行从 x − start 开始画
```

要点：

1. **节奏由文本决定，不由行程决定。** `content` 只看整行有多少列，与这一行要滚多远无关。于是同一批词在窄栏里滚得更快而不是更久——时钟页那条正是旧算法的失效点：按行程定时长时，窄栏把行程放大 1.87 倍，时长也放大 1.87 倍，一句 8 秒的歌词被排成 12.2 秒，第 8 秒只走了 61 %。
2. **`line_end` 只能压短，不能拉长。** 句子短时（`budget` 比 `content` 小）滚动被压进本句时间，末字在换句前到达；句子后面跟着长间奏时（`budget` 很大）用 `content`，滚完就停在终态，不会像旧方案那样把速度摊薄到整段间奏。
3. **收尾留 400 ms，停顿最多占可用时间的三分之一。** 面板 250 ms 组一帧，若滚动正好在换句那一刻结束，换句前的最后一帧必然差一格，末字永远看不到——英文快歌一句只有 1–4 秒时，这个差额占到 5–15 %。留出 400 ms 保证终态至少被完整画出一帧；同时把剩下的时间优先给滚动，停顿只在有余量时才保留，否则压缩的是运动而不是停顿。
4. **整尾对齐。** `travel` 取 `tail_start`：从行尾往回累加整字宽度，找到「整条尾巴能放进一行」的最左字形边界。直接按 `width − room` 算终位时，量化可能比这个边界多走 12 px，最后一个字会被整字裁掉——中文行约有一半会命中，正好是"看不到最后 1–2 个字"。
5. **整字裁剪。** `boundary_at_or_before` / `window_width` 保证裁剪窗左右两端都落在字形边界上，滚动过程中不会出现半个字。纯像素裁剪在 1-bit 屏上会把半个字显示成像「口」的方框。
6. **每句只算一次 `budget`。** 没有时间轴时，锚点是"这一行的文字变了"的那一刻（`apply_now_playing` 比较当前行文本），句内重复发布不重锚、不重算上限，位置抖动不会改动速度。有时间轴时 `budget` 是这一行自己的长度，与发布时机无关。
7. **换句从头开始。** 新句从行首、静置 900 ms 起播；暂停时停在行首，不滚走。
8. **只滚正在唱的那行。** 其余行是上下文，用 `fit` 截断加省略号。
9. **没有新发布就不外推。** 3 秒（约三次发布）没有新帧，播放位置就停在最后听到的地方；一次漏发仍在窗口内。
10. **面板自己换句。** 有时间轴时，正在唱的那一行由播放位置算出，发布只负责补充窗口；面板用本地时钟把播放位置往前推，所以换句最多差一个链路延迟，而不是一个发布周期。算出来的行一旦和上一帧画的行不同（`music_line_moved`），主循环立刻组一帧，不等 250 ms 边界——否则换句会再晚最多一帧。

## 参数

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `kLyricScrollColumn` | 12 px | 一列文字；偏移与裁剪都按它量化 |
| `kLyricLeadInMs` | 900 ms | 行首静置的上限，先看清开头；时间紧时按 `usable/3` 收缩 |
| `kLyricBaseMs` | 900 ms | 每行的固定阅读开销 |
| `kLyricColumnMs` | 100 ms | 每列文字的阅读时间（汉字约 0.2 s） |
| `kLyricEndMarginMs` | 400 ms | 收尾提前量，保证终态至少被画出一帧 |
| 行缓冲 | 192 字节 | 协议上限；一句最多 64 个汉字 |

一句话 45 列时：内容时长 5.4 s，加前导共 6.3 s。时钟页 336 px 行程 → 62 px/s，歌词页 180 px → 33 px/s。

## 边界情况

| 情况 | 行为 |
| --- | --- |
| 整行放得下（`travel ≤ 0`） | 不滚，静态显示 |
| 没有 `line_end`（最后一句、旧版 Bridge） | 只用 `content`，滚完停在终态 |
| `line_end ≤ position` | 视为没有上限 |
| 没有 `line_times`（旧版 Bridge） | 按发布时刻计时，换句最多晚一个发布周期 |
| 超过 3 秒没有新发布 | 播放位置停在最后听到的地方，歌词不再前进 |
| 窗口里的最后一行 | 没有后继，长度未知（`budget = 0`），只用 `content` |
| 剩余时间不足 1 s | 停顿压缩到 `usable/3`，剩余全部给滚动，仍提前 400 ms 收尾 |
| 一句几十个字（192 字节上限） | `content` 变大但有 `budget` 压着，不会拖过本句 |
| 间奏 | `budget` 很大 → 取 `content`，滚完停住，间奏期间不动 |

## 验证

- 单元测试：`firmware/targets/waveshare_rlcd_42/test_apps/logic/main/test_panel_logic.cpp`（曲线数值、整列对齐、上限只压短不拉长、锚点只在换句时复位、时间轴上的滚动年龄与换句）与同目录 `test_screens.cpp`（整尾对齐、只有当前行滚、裁剪不越界、时间轴决定高亮哪一行）。
- 时间轴仿真：用一首英文快歌的真实 LRC（相邻句间隔 1–4 s）逐句计算"换句前的最后一帧是否到达终位"，在 0 / 500 / 900 / 1000 / 1500 ms 的发布延迟下均为 0 句失败。
- 渲染验证：`tools/rlcd42/render_preview.cpp` 生成全部页面；另用临时驱动渲染同一句在 0 / 2 / 4 / 6.3 / 8 / 30 秒的帧，确认 6.3 秒即终态、30 秒与终态逐字节相同。
- 行为回归：34 页预览与改动前逐字节一致（短句行为未变）。
