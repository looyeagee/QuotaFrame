# 会话名单的逐像素滚动

本文说明 AMOLED 1.8 面板的会话页如何做到「跟手」：手指移动多少像素，名单就移动多少像素。
实现见 `firmware/targets/waveshare_amoled_18/main/board.cpp`（手势判定）、
`firmware/components/usage_panel/src/panel_logic.cpp`（滚动与夹取）、
`firmware/targets/waveshare_amoled_18/main/screens.cpp`（按像素画名单）与
`firmware/targets/waveshare_amoled_18/main/sh8601.cpp`（只发变化的条）。

## 约束

- 触摸控制器 FT3168 挂在 400 kHz 的 I2C 上，主循环轮询它；一次读一个点，失败一次会 NACK，
  下一次读补上（位移按两次成功读之间的差算，所以失败不丢位移）。
- 玻璃 368 × 448，RGB565 一帧 322 KiB，在 PSRAM 里。QSPI 40 MHz，4 条数据线，整帧上总线
  约 17 ms；一帧按 32 行一条发，一条 23 KiB，约 1.2 ms。
- 名单一行 74 px（卡片 60 px + 间隔 14 px），玻璃一次画四行，名单最多 24 行。
- 面板 4 fps 组帧（250 ms 一帧）只用于让秒数走字；滚动时每次手指移动都立刻组帧。

## 之前的问题

滑动是「松手才判定」的一次性动作：一次滑动 = 一行。于是名单只能一格一格跳，手指停在两行
中间时画面停在一行的边界上，看起来跟手差得很远。方向判定还用的是玻璃的原始坐标，
只有动作方向才映射到逻辑坐标，于是 90° 时上下拖动被判成了翻页。

## 手势判定

手指按下后位移达到 8 px 时判定方向，判定在**逻辑坐标**里做（`logical_delta` 把玻璃坐标
映射到页面坐标，和画布绘制用的是同一个映射），所以每个方向下拖动都沿着名单：

- 竖向为主 → 锁定为拖动名单；
- 横向为主 → 锁定为翻页。

锁定之后不再改判：这是常见的方向锁，避免拖到一半突然换页。判定之前的位移不丢，它先攒
着，等锁定为拖动时连同这一段一起交出去。

拖动期间每次轮询都把「上次读到的位置到这次读到的位置」的位移换算到逻辑坐标后交给运行
时。松手时不再补发动作：名单停在哪里就是哪里。

## 滚动模型

视图里记的不是行号，是**上移了多少像素**（`View::sessions_scroll_px`）。面板知道名单的
几何：行高与可见行数由目标在渲染时交给运行时（`SessionsGeometry`），运行时据此把偏移夹在
名单末尾之内：

```
limit = max(0, 名单行数 − 可见行数) × 行高
offset = clamp(offset + 本次位移, 0, limit)
```

名单变短时（Bridge 下发了更小的名单）偏移按同一个上限夹回去，所以不会出现指着已经不存
在的行。没有几何的目标（RLCD 4.2、ZLTech 1.54）上限是 0，拖动不动任何东西。

## 画名单

`Screens::sessions` 把像素偏移拆成「起始行」与「行内偏移」：

```
first  = offset / 行高
shift  = offset % 行高
```

第 `first` 张卡片画在窗口顶部再上移 `shift` 像素。名单画在名单区域（计数下面、页码点上面）
的裁剪框里：滑出顶部的卡片在计数下面消失，从底部升上来的卡片补上滚动留下的空位，所以画
多一张卡（`first … first + 可见行数`），末尾多出来的那张在整行对齐时被裁掉。芯片宽度按整
份名单算，滚动时列不会左右跳。

## 帧率

手指移动时主循环把休眠缩短到 2 ms，读触摸更密，位移的累加更贴近手指。发送按条比较：与
屏上内容相同的条不上总线，拖动时只有名单那几条变，页面上的计数、页脚、页码点不动。

还没有做的是甩动（松手后的惯性滚动）与边界回弹；这一版只保证手指按住时一一对应。

## 验证

主机渲染核对：9 行名单滑到第 5 行给 `5-8 OF 9`，停在两行之间时卡片被计数切掉一半、底部
的卡片升上来一半（`tools/wsamoled18/render_preview.cpp` 的 `17_sessions_half_row`）。
导航逻辑有用例覆盖（`firmware/targets/waveshare_rlcd_42/test_apps/logic/main/test_panel_logic.cpp`）。
玻璃上的手感与帧率仍待实机确认。
